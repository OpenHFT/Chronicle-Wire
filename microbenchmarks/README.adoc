== Purpose

Chronicle Wire separates *what* data you store or retrieve from *how* it is rendered and parsed. It supports a range of human-readable and binary formats. This document summarises how format choices affect performance and payload size, and shows the minimal code needed for each approach.

== Test Environment

* JVM flags: `-Xmx1g -XX:MaxInlineSize=400`
* CPU isolation: single core
* Hardware: Intel i7-3970X, 32 GB RAM
* Methodology: latency benchmarks with 10 forks to capture run-to-run variance (high percentiles tend to reflect the slowest fork)
* Full results: https://github.com/OpenHFT/Chronicle-Wire/tree/master/microbenchmarks/results[Chronicle Wire microbenchmarks results]

NOTE: All latency figures are in micro-seconds.

== Code: Wire Marshalling

You can implement `readMarshallable` and `writeMarshallable` on your domain class to use Wire:

[source,java]
----
@Override
public void readMarshallable(WireIn wire) throws IllegalStateException {
    wire.read(DataFields.price).float64(this::setPrice)
        .read(DataFields.flag).bool(this::setFlag)
        .read(DataFields.text).text(this::setText)
        .read(DataFields.side).asEnum(Side.class, this::setSide)
        .read(DataFields.smallInt).int32(this::setSmallInt)
        .read(DataFields.longInt).int64(this::setLongInt);
}

@Override
public void writeMarshallable(WireOut wire) {
    wire.write(DataFields.price).float64(price)
        .write(DataFields.flag).bool(flag)
        .write(DataFields.text).text(text)
        .write(DataFields.side).asEnum(side)
        .write(DataFields.smallInt).int32(smallInt)
        .write(DataFields.longInt).int64(longInt);
}
----

== Code: BytesMarshallable

`BytesMarshallable` is faster and smallest, but you lose self-describing structure and easy visualisation. Schema evolution also requires more care.

[source,java]
----
@Override
public void readMarshallable(Bytes<?> bytes) {
    price   = bytes.readDouble();
    longInt = bytes.readLong();
    smallInt = bytes.readInt();
    flag    = bytes.readBoolean();
    // side = bytes.readEnum(Side.class); // alternative
    side    = bytes.readBoolean() ? Side.Buy : Side.Sell;
    bytes.read8bit(text);
}

@Override
public void writeMarshallable(Bytes<?> bytes) {
    bytes.writeDouble(price)
         .writeLong(longInt)
         .writeInt(smallInt)
         // .writeEnum(side) // alternative
         .writeBoolean(flag)
         .writeBoolean(side == Side.Buy)
         .write8bit(text);
}
----
TIP: Encoding an enum as a boolean saved a few bytes in this example.

== Notes on Specific Libraries

=== SBE (Simple Binary Encoding)

SBE can perform as well as BytesMarshallable. In these tests it was slightly slower, but the gap is small and workload-dependent. SBE is powerful but setup is non-trivial; for a flat class with six fields it generated multiple helper classes, and manual tweaking was helpful for peak performance.

=== SnakeYAML

SnakeYAML is a complete YAML 1.1 parser. The breadth of the spec means more work per message and higher latency. It is the right tool when you must accept general YAML; otherwise, a lightweight wire format may be more suitable for low-latency needs.

== Format Examples

The examples below show representative encodings. For human-readable dumps, Wire adds a size prefix (4 bytes) and may annotate with markers like `!!data` and `#binary`.

side: Sell

----

== Takeaways

* For minimum latency and size, `BytesMarshallable` (optionally with stop bit encoding) is best, at the cost of readability and schema evolution flexibility.
* `BinaryWire` with numbered fields and, when suitable, fixed widths, is a strong balance of speed, size, and developer ergonomics.
* Text formats (YAML/JSON) are slower but easier to read, document, and debug. Switching between text and binary during development is often productive.
