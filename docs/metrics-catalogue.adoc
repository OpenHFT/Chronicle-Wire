= Chronicle metrics catalogue
:toc:
:toclevels: 2

The authoritative registry of every metric the Chronicle portfolio emits through the
`net.openhft.chronicle.wire.metrics` API (review item #48). It was built by inspecting the
registration calls and reused-DTO builders in the emitting sources of every instrumented
repository; when this document and the code disagree, the code wins and this document must be
fixed in the same change.

Companion document: link:metrics-integration.adoc[metrics-integration.adoc] - where to
install the binding, which integrations are startup-only vs runtime-toggleable, and the
metrics-queue topology.

Design reference: `p1-chronicle-metrics-design-2026-07-03.md` (workspace root), sections 6
(on-queue schema and naming conventions) and 8 (gateway).

== Conventions

* Names follow `chronicle_<product>_<subsystem>_<metric>_<unit>`: `_total` for counters,
  units in the name (`_ns`, `_bytes`, `_ratio`, `_indices`, `_percent`).
* *Kind* is the on-wire event kind (the `MetricsOut` method name): `counter`, `gauge`,
  `histogram`, `rate` or `point event`. The gateway exports point events as Prometheus
  counters counted since gateway start/replay (a `_total` suffix is appended when missing);
  histograms export as fixed-quantile summaries plus `_sum`/`_count` - *not aggregatable
  across hosts*.
* *Source* is the dotted source name carried on every event
  (`chronicle.<product>.<subsystem>`), used for log-level-style selection
  (`SourceSelection`) and gateway routing.
* *Cadence*: `per-flush` metrics are recorded into instruments/DTOs and emitted on an owner
  or host cadence; `per-event` metrics are emitted at the moment of the underlying event.
* *Since* is the first release train carrying the metric (the emitting repository's
  in-flight version at the time of writing; all listed integrations are currently
  uncommitted work targeting that release).
* The gateway may decorate every exported producer series with per-source `extraLabels`
  (e.g. `host=prod-a`) from its configuration and always adds the reserved Prometheus
  label `chronicle_source` from the producer source key carried on the metric event.
  Prometheus adds `job`/`instance` at scrape time. These exporter-side labels do not appear
  in the producer label columns below because producers do not emit them.

by the host: `Metrics.registry(QueueMetrics.APPENDER_SOURCE).flush(out, eventTime, intervalNs)`.

== Chronicle Threads - event loops (`chronicle.threads.eventloop`)

Emitting class: `net.openhft.chronicle.threads.internal.EventLoopMetrics`, hooked into
`MediumEventLoop` (and its subclass `VanillaEventLoop`); other loop types are deliberately
not instrumented. Startup-only policy (resolve-once at loop construction). Each loop owns an
independent registry (`Metrics.newRegistry`) flushed by the loop itself every
`chronicle.threads.metrics.flush.interval.ms` (default 1 s); the registry is closed
(instruments deregistered) when the loop closes.

Labels on every instrument: `loop` (the loop name); `service` (*optional* - only when the
`chronicle.metrics.service` system property is set and non-empty, read at loop construction).

[cols="3,1,1,2,1",options="header"]
|===
| Metric | Kind | Unit | Cadence | Since

| `chronicle_threads_eventloop_task_latency_ns` | histogram | ns
| sampled per busy iteration, emitted per-flush | 2026.4

| `chronicle_threads_eventloop_busy_ratio` | gauge | ratio 0..1
| per-flush (fraction of the window in busy iterations) | 2026.4

| `chronicle_threads_eventloop_idle_ratio` | gauge | ratio 0..1
| per-flush (fraction of the window measured idle; busy+idle ~= 1, shortfall = stall) | 2026.4

| `chronicle_threads_eventloop_iterations_total` | counter | iterations
| recorded per iteration, emitted per-flush | 2026.4
|===

== Chronicle Network - connections (`chronicle.network.connection`, `chronicle.network.heartbeat`)

Emitting class: `net.openhft.chronicle.network.MetricsConnectionListener` (installed via
`addConnectionListener(...)`). Runtime-toggleable (facade + unwrap at emission time).

Labels: `remoteId` (bounded cluster host identifier - never a socket address) and
`isAcceptor` (`true`/`false`) on every connection point event; user labels added via
`label(key, value)` before the first event (*optional*, e.g. `cluster`) are prepended.
The heartbeat gauge carries only the *optional user labels* (it aggregates across peers).

== Cardinality guidelines

These rules (review item #49) bound the number of time series any Chronicle producer can
mint. A time series is expensive forever; a label value is a series multiplier.

*Labels must be bounded, enumerable sets.* Before adding a label, you must be able to state
its maximum cardinality from configuration or code - number of queues on the host, number
of configured cluster peers, number of event loops, number of services in the runner
configuration, the ring's reader-table size. Every label in this catalogue is justified
that way (see the per-product notes above, e.g. Network's `remoteId` reasoning and MDD's
resolver contract).

*Explicitly banned as label values:*

* *Order IDs, message IDs*, trade IDs, correlation IDs - per-message data is *data*, not a
  label; it belongs on a business or trace queue.
* *Raw unbounded session or tailer names* - anything user- or client-supplied that is not
  drawn from a bounded configured set. Where a name-shaped label is unavoidable, cap and
  evict, as `NamedTailerAckLagMetrics` does (`MAX_TAILERS` = 1024, idle eviction), and
  document the cap.
* *Timestamps, socket addresses, ephemeral ports, connection ids* - a new value per
  connection attempt means a new series per attempt (this is exactly why
  `MetricsConnectionListener` labels the bounded `remoteId`, never `host:port`).
* *Symbols / instruments as labels*, `key=<symbol>` style, *unless* the instrument universe
  is bounded and documented - i.e. it is a fixed, configured set (such as MDD's
  `0..maxKeys-1` key space mapped through a bounded `keyName` resolver), and the maximum
  count is stated where the resolver/label is configured. An open-ended symbol space (any
  tradable instrument, client-supplied symbology) is banned.

*Series-identity rule.* A series is identified by *name + the concatenated labels string*
(`key=value;key2=value2`), with keys in *registration order*; that order is canonical.
`name{a=1;b=2}` and `name{b=2;a=1}` are *different series* - producers must register labels
in one fixed order and reuse the DTO, never rebuild label strings in varying order.
Registries dedup instruments on (kind, name, labels) under the same rule.

*Practical checks.*

* Label keys must match `[a-zA-Z_][a-zA-Z0-9_]*` (Prometheus-valid), values must be
  non-null; `=` and `;` are structural in the concatenated form and are sanitized to `_` by
  the producers in this catalogue.
* Estimate worst-case series: multiply each label's bound (e.g. Network:
  `peers x 2 roles x 3 names`). If you cannot write that product down, the label set is not
  bounded and must not ship.
* The gateway rejects and counts invalid names/labels
  (`chronicle_gateway_invalid_metrics_total`) rather than adopting them - a producer that
  violates these rules becomes visible, not stored.
